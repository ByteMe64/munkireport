# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This repo is **not** the MunkiReport application — it is a deployment wrapper that builds and runs upstream [munkireport-php](https://github.com/munkireport/munkireport-php) in containers. The PHP application source is downloaded inside `Dockerfile` at build time (pinned via the `MUNKIREPORT_VERSION` build arg, currently `5.8.0`) — it is never checked into this repo. To change application behavior, you generally change the image build, the env vars passed in `docker-compose.yml`, or the upstream version pin — not source files here.

Everything in the repo:

- `Dockerfile` — builds the MunkiReport image on Ubuntu 24.04 + PHP 8.5 + Apache 2.4.
- `docker-compose.yml` — full stack: Traefik (TLS) → MunkiReport → MariaDB 11.4, plus two init containers.
- `.env` — secrets and host-specific values. Gitignored and not tracked; the local working-tree copy ships with placeholder `CHANGE_ME_*` values that must be replaced before deploy.
- `client-setup.sh` — runs on a **Mac client**, not the server; installs the MunkiReport agent against a deployed server.

## Common commands

```bash
# Deploy / redeploy the full stack
docker compose up -d --build

# Rebuild only the MunkiReport image (after changing Dockerfile or bumping version)
docker compose build munkireport && docker compose up -d munkireport

# Tail logs
docker compose logs -f munkireport
docker compose logs -f traefik

# Reset everything including DB (destructive)
docker compose down -v
```

There are no tests, linters, or build scripts — this is pure infrastructure config.

## Architecture notes that aren't obvious from one file

### Portainer-ready: no host bind mounts, no Docker socket

The stack is intentionally designed to deploy via Portainer with zero host filesystem prerequisites:

- **No bind mounts** — all persistent state is in named Docker volumes (`munkireport-db`, `munkireport-users`, `munkireport-data`, `traefik-certs`, `traefik-config`).
- **No Docker socket exposure** — Traefik uses the **file provider**, not the Docker provider. Routing config is generated by the `traefik-init` busybox container at deploy time and written into the `traefik-config` named volume, which Traefik then mounts read-only.

If you find yourself reaching for `volumes: - ./something:/something` or `/var/run/docker.sock`, reconsider — the init-container pattern is the deliberate alternative.

### Admin user provisioning via `munkireport-init`

MunkiReport reads admin users from YAML files in `local/users/`. The `munkireport-init` busybox container writes `admin.yml` into the `munkireport-users` named volume before the main app starts. The credentials come from `.env`: `ADMIN_USERNAME`, `ADMIN_REALNAME`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD_HASH`.

**Password hash quoting** (this trips people up): in `.env`, wrap the bcrypt hash in single quotes — `ADMIN_PASSWORD_HASH='$2y$10$abc...'` — so docker compose does not interpolate the `$` characters as variables. The hash is then passed into the busybox container as an env var and written out with `printf '%s'`, so no further escaping is needed.

Generate a hash with `./generate-admin-hash.sh`, paste the output line into `.env`, then `docker compose up -d --force-recreate munkireport-init && docker compose restart munkireport`. The `--force-recreate` is what actually re-runs the init container and overwrites `admin.yml` in the volume.

### TLS / Let's Encrypt

Traefik does HTTP-01 ACME on port 80 → certs land in the `traefik-certs` volume at `/letsencrypt/acme.json`. `DOMAIN` in `.env` **must** have a public A record pointing at the host before first deploy, or ACME issuance fails and you'll get self-signed cert errors. Traefik redirects all `:80` → `:443`.

### Client ↔ server passphrase

Mac clients authenticate to the server by sending a shared secret. The same value must appear in two places:

- Server side: `CLIENT_PASSPHRASE` in `.env` (passed to the container as `PASSPHRASE`).
- Client side: `PASSPHRASE` at the top of `client-setup.sh` (written to `/Library/Preferences/MunkiReport.plist` on the Mac).

If they don't match, clients silently fail to register.

### Enabled modules

The `MODULES` env var on the `munkireport` service is the canonical list of dashboard modules to enable. Adding or removing a module is an env-var change + container restart — no rebuild needed.
